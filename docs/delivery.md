# 发送保护设计

保护层包装 OneBot v11 的 `Adapter._call_api`，因此正常聊天、命令回复、ACM 题面、管理员工具、合并转发和本地发送 API 共用一个发送预算。读取接口不会被发送冷却阻塞。策略文件为运行目录的 `delivery-policy.json`，示例见 `config/delivery-policy.example.json`；所有字段经过类型和范围校验，无效配置会阻止桥接启动。

## 发送记录

实际调用前写入 `pending`。有消息 ID 才确认消息发送成功；上传文件以正常接口返回为准。异常、取消或者没有消息回执均保守保留为结果不明，不重试实际发送。成功重复请求复用原消息 ID；不同对象、不同内容各自独立。

数据库 `.delivery-guard.sqlite3` 仅记录本地加盐 HMAC、时间、状态和回执 ID，不保存消息正文、图片字节或异常原文，权限为 0600。记录按时间清理，冷却、连续失败计数和最后确认时间持久保存。该数据库不进入 Git。

所有发送在同一异步锁内串行提交；限速等待计入等待上限，网络调用开始后不因队列上限取消它。队列中取消的请求会正确释放名额；已经开始网络调用的取消请求保留结果不明记录。显式 `SendBlocked` 是本次调用未开始发送，绝不伪造成功。

本地 `/send` 和 `/action` 在网络调用前遇到保护时返回 `state=not_sent`；已开始或部分完成的分段请求仍为 `uncertain`。原有 request_id 幂等记录保留，不能通过更换 request_id 猜测重发。服务器付费抽题、题面接收确认、判题状态和现有请求幂等逻辑均未改变。

## 状态检查

认证 `GET /hermes-outbound/health` 返回：

| 字段 | 含义 |
| --- | --- |
| `transport_reported_online` | QQ/OneBot 自报在线，不是端到端验证 |
| `last_inbound_at` | 桥接最近收到真实消息的时间 |
| `last_confirmed_send_at` | 最近收到成功发送回执的时间 |
| `delivery_state` | 最近已知发送结果：未验证、确认或异常，不保证当前网络状态 |
| `send_paused` / `retry_after` | 是否冷却及剩余秒数 |
| `pending` | 当前正在发送或等待的请求数 |

检查不会主动发送测试消息。保护层只在真实请求发生时更新发送状态，不能凭空发现所有静默断网；登录态失效仍需用户扫码。不会自动重启客户端或清除登录信息。

## 和平台规则的关系

官方 QQ 机器人消息接口另有场景、权限及回复窗口要求，见 [腾讯官方发送消息文档](https://github.com/tencent-connect/bot-docs/blob/main/docs/develop/api-v2/server-inter/message/send-receive/send.md)。本项目目前使用本地 OneBot/NapCat，因此不能把官方接口的配额当作个人 QQ 客户端的保证。这里的间隔和预算只是减少刷屏、重试风暴及误报在线的工程措施。

验证采用假发送器，覆盖并发重复、跨会话隔离、分钟预算、队列取消、重启后的去重/冷却、无回执及异常恢复；不会对真实好友/群发送测试消息。
